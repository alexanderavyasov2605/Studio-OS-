# Каталог — этап 5

Запуск: pnpm install --frozen-lockfile, pnpm db:migrate, pnpm db:seed, pnpm dev. Требуется DATABASE_URL. Для админки также APP_ORIGIN и собственный первый администратор по [AUTH](AUTH.md).

dev/build используют обычный Next CLI через scripts/next.mjs; на Windows включается ограниченная обработка временного mkdir/EPERM в .next-auth. Приложение и права файлов не меняются. pnpm test:routes теперь также требует настроенную БД каталога.

## Публичная часть
/catalog читает PostgreSQL при каждом запросе: активные товары только в активных категориях, поиск по названию без учёта регистра, совместная фильтрация категорией, страницы по 24 изделия. Порядок: sortOrder, затем стабильный id. Адреса фильтров сохраняются в URL. /catalog/[slug] показывает описание, особенности, иллюстрации и материалы с фактическим статусом; выключенные изделия и категории возвращают 404. Архивные материалы не показываются.

Loading/error/empty/404 и ошибка загрузки изображения имеют отдельное отображение. Описание и особенности — обычный текст, HTML не исполняется. Данные не кешируются между запросами: сохранённый администратором товар появляется без изменения кода и пересборки.

«Рассчитать стоимость» ведёт в существующую оболочку /configure/[slug]. Карточка прямо сообщает, что калькулятор и приём заявок ещё не подключены. AUTO_SHEET задаёт намерение листового расчёта, MANUAL_REQUEST — ручного. Наличие режима и материала не создаёт технологическую совместимость или действующий тариф.

## Администрирование
/admin/catalog: список категорий и товаров; создание, редактирование, включение, описание, особенности, изображения, материалы, режим и числовая сортировка. Меньшее число — выше на витрине. Выключенные категории доступны в справочнике, но не допускают публикацию товара.

Изображения задаются HTTPS-ссылками и альтернативными описаниями, до 6 строк в порядке галереи. Файлы предварительно размещают в существующем Supabase Storage; загрузчик файлов и дополнительные хранилища не создавались. Стартовые /catalog-art/*.svg — локальные векторные иллюстрации изделий, не фотографии изготовленной продукции. Браузер загружает внешние изображения напрямую с no-referrer; привилегированного серверного прокси загрузки нет.

ADMIN имеет право записи. OPERATOR по умолчанию только смотрит; для записи требуется явное catalog:write в User.permissions. API не принимает роли/права. POST /api/admin/catalog/products создаёт, PUT /api/admin/catalog/products/:id полностью редактирует товар; GET /api/admin/catalog возвращает защищённый справочник. Проверки сессии, Origin, JSON (до 32 KiB) и прав обязательны. Сессия/пользователь/версия пароля повторно проверяются под блокировками в едином auth-модуле. Товар, изображения, материалы и аудит сохраняются одной транзакцией.

revision защищает от перезаписи параллельных изменений (409). Повтор адреса также возвращает 409. После конфликта нужно открыть актуальный товар заново. Публичной регистрации, удаления товаров и изменения ролей нет.

## Данные и seed
Product: calculationMode, features, sortOrder, revision. ProductImage — упорядоченная галерея; ProductMaterial — витринный выбор материала, отдельный от ProductCompatibility с технологическими профилями. Индексы, ограничения и RLS находятся в миграции 20261103090000_catalog.

Seed создаёт три категории и пять товаров: бумажные наклейки (AUTO_SHEET), виниловые и прозрачные наклейки (MANUAL_REQUEST), бирки и упаковочные карточки (AUTO_SHEET). Пять материалов — ON_REQUEST; подтверждённое наличие, цены, стойкость и оборудование не выдумываются. Повторный seed не перезаписывает правки, выключение, сортировку, изображения или изменённый адрес начального изделия; его идентичность стабильна.

## Проверки
pnpm test — границы слоёв, поля и безопасные URL. pnpm db:test — пустая одноразовая PostgreSQL, миграции, повторный seed и инварианты. pnpm catalog:test — локальная production-сборка с AUTH_TEST_BASE_URL, APP_ORIGIN и отдельной DATABASE_TEST_URL после миграций/seed; создаёт только синтетических сотрудников и товары. Не запускать интеграционные проверки на рабочей БД.

Проверяются создание → публичная карточка без сборки, изменения, комбинированный поиск/категория, литеральный %, сортировка, выключение/404, права оператора, CSRF, валидация, конфликты revision/slug и аудит. Бизнес-операции остаются в server/catalog, auth в server/auth, UI получает только DTO. Серверные страницы импортируют отмеченные server-only адаптеры.
